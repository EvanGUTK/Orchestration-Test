## Frozen engine decisions

1. Seed: `SHA-256(UTF-8("2048-infinite/v1:" + seed))`, first 16 bytes -> 4 LE uint32; all-zero -> `[1,0,0,0]`.
   Bots derive from `"2048-infinite/bot/v1:" + seed` and never touch a game's `rng`.
2. PRNG `xoshiro128ss-v1`: standard xoshiro128** (`rotl(s1*5,7)*9`), all uint32 wraparound.
3. `uniform(n)`: `limit = 2^32 - (2^32 mod n)`; draw until `x < limit`; return `x mod n`. Every raw draw,
   including rejected ones and the single draw for `n = 1`, advances state (QA question 1: confirmed).
4. Spawn: empty indexes row-major; position draw `uniform(emptyCount)` then value draw `uniform(10)`;
   exponent `"2"` if `v < rules.fourWeight` else `"1"`. `fourWeight` is an integer 0..10 (QA question 4: confirmed).
5. `rulesetVersion` comes from the `Ruleset` passed in (QA question 3: the vectors pass `classic-v1` rules for 4x4
   and `practice-v1` rules for other sizes; a 4x4 *practice* game passes `practice-v1` and is labelled so).
6. After a changed move: slide, add score, spawn once, `acceptedMoves += 1`, `revision += 1`; then on the
   post-spawn board (QA question 5: confirmed) set `celebrated2048` once when any exponent >= 11, set
   `status = "completed"` if the board is dead OR `rules.moveCap !== null && acceptedMoves >= rules.moveCap`.
   No-op: return the identical state object values, `changed:false`, `scoreDelta:"0"`, zero draws, no events.
7. `applyMove` on a non-active game throws `EngineError` code `GAME_NOT_ACTIVE` (QA question 2: chief decision).
8. Canonical JSON key order = `CANONICAL_STATE_KEYS` (board: size, cells; rng: algorithm, words), no whitespace;
   checksum = lowercase hex SHA-256 of its UTF-8 bytes. The engine ships a pure synchronous TS SHA-256
   (no `node:crypto`, no WebCrypto) so it runs identically in browser, Node, and workers.
9. Event order: see `DomainEvent` doc comment in `src/domain.ts`.
10. Resource guard: creating an exponent above `LIMITS.maxExponent` throws `EngineError("RESOURCE_LIMIT")`
    before computing the power; input state is untouched.

## Engine public API (`@g2048/engine`)

```ts
class EngineError extends Error { code: EngineErrorCode }
newGame(rules: Ruleset, seed: string): GameState
slide(board: Board, direction: Direction): SlideResult            // no randomness
applyMove(state: GameState, direction: Direction, rules: Ruleset): MoveResult
forfeit(state: GameState): GameState                              // status "forfeited", same rng/score
legalMoves(board: Board): Direction[]                             // order up,right,down,left
isGameOver(board: Board): boolean
maxExponent(board: Board): Exponent | null
canonicalJson(state: GameState): string
checksum(state: GameState): string
serialize(state: GameState): string                               // = canonicalJson
deserialize(json: string): GameState                              // validates; EngineError on bad input/version
deriveRandomState(namespace: string, seed: string): RandomState
nextUint32(rng: RandomState): [number, RandomState]
uniform(rng: RandomState, n: number): [number, RandomState]
replay(initial: GameState, moves: readonly Direction[], rules: Ruleset): { final: GameState; checksums: string[] }
verifyReplay(file: ReplayFile, rules: Ruleset): { ok: true; final: GameState } | { ok: false; code: EngineErrorCode; atMove: number | null; message: string }
decimal helpers: compareDecimal(a, b): -1|0|1, addDecimal(a, b), pow2Decimal(e: Exponent)
```

All functions are pure; inputs are never mutated (freeze in tests). No clocks, I/O, `Math.random`.

## HTTP / WebSocket / DB

- HTTP: `docs/CONTRACTS.md` table + request schemas and response types in `src/api.ts`; error envelope
  and statuses in `src/errors.ts`; limits in `src/limits.ts`. Base `/api/v1`.

  `x-csrf-token` equal to the session's CSRF token from `GET /auth/me`. Cookies: `sid` (account) and
  `gid` (guest), `HttpOnly; SameSite=Strict; Path=/`.
- WebSocket: `src/ws.ts`. Events are sent only after the DB commit.

  Dev: Vite on `$WEB_PORT` (5412) proxies `/api` (HTTP + WS) to `$API_PORT`.

## Clarifications (non-breaking, after ENGINE-003 / QA-002)

- C1. Version mismatch on a loaded state (`schemaVersion`, `engineVersion`, rng `algorithm`, `replaySchemaVersion`)
  => `REPLAY_VERSION_UNSUPPORTED` from `deserialize`, `applyMove`, `verifyReplay`.
- C2. A loaded state that already contains an exponent above `LIMITS.maxExponent` is invalid input
  => `VALIDATION_ERROR`. `RESOURCE_LIMIT` is reserved for a transition that would create such an exponent.
- C3. Merge event `sources` = `[leading tile, trailing tile]` in the slide direction.
- C4. `first2048` is true only on the milestone of the move that flips `celebrated2048`.
- C5. `forfeit` changes only `status` (revision/acceptedMoves unchanged); non-active input => `GAME_NOT_ACTIVE`.
- C6. Move-cap completion sets `status: "completed"` without a `game.over` event; consumers read `state.status`.
- C7. `verifyReplay` rejects no-op moves and requires `initialState` to equal `newGame(rules, seed)`.
- C8. `preferences.keyBindings` is a partial record (any subset of directions). Register/login return
  `AuthResponse` (= `MeResponse`); session clearing is `POST /auth/logout` with `{ "allSessions": true }`;
  logout and password change return `RevokeResponse` `{ ok: true, revokedSessions }`.
- C9. `chooseMove` returns a tagged union: `{ kind: "move", decision, rng }` or
  `{ kind: "no-legal-move", reason: "dead-board" | "game-not-active", rng }`. Bot strategies read only
  `state.status` and `state.board`. The Node runner is the `@g2048/bots/runner` entry; time budgets apply only
  when a clock is injected (tournaments are node-budget only and machine-independent).
- C10. `legalMoves`/`isGameOver` reflect game rules only. A move that would create an exponent above
  `LIMITS.maxExponent` stays "legal"; applying it fails with `RESOURCE_LIMIT` and preserves the state (the game is
  never declared over or won because of the resource guard).
- C11. Undo beyond the casual history limit (100) or with nothing left to undo => 400 `VALIDATION_ERROR`
  (state unchanged). 403 `FORBIDDEN` is only for modes where undo is not allowed (ranked/duel/undo-disabled practice)
  and for ownership.
- C12. `ReplayFile.moves[].revision` is the canonical replay revision (1..n over the accepted moves on the final path,
  exactly what `engine.replay`/`verifyReplay` produce), not the server's internal game revision (which also counts
  undo/forfeit commands). Exporters re-derive per-move checksums with `engine.replay`.
- C13. Bot runs: `GET /bots/runs/:id` returns `BotRunView` (owner only) for polling; `bot.progress`/`bot.finished`
  WebSocket events mirror it. Pause/resume/step live under `POST /bots/runs/:id/{pause,resume,step}`.
- C14. Game command responses: `POST /games` → 201 `GameResponse`; moves → 200 `MoveResponse`; undo/forfeit
  (`RevisionCommandRequest`) → 200 `GameResponse`; a repeated commandId returns the originally stored response;
  commands on a non-active game → 409 `REVISION_CONFLICT` if the revision is stale, else 403 `FORBIDDEN`.
- C15. Ownership handoff (chief, for BACKEND-005 parallelism): the competition lane owns the NEW directories
  `apps/server/src/matches/**` and `apps/server/src/realtime/**`; backend keeps every other server/database path,
  including `app.ts` registration and migrations. Generic `/games/:id/*` routes serve only classic/practice games;
  ranked attempts and duel seats use mode-restricted internal game-service methods (SEC-R2-02).
- C15a. Amendment: ranked challenge games use the generic `/games/:id/moves` and `/games/:id/forfeit` routes with
  mode-aware delegation (ranked ruleset: undo 403, 500 cap, attempt bookkeeping in the same transaction). Duel and
  bot-vs-bot games are 404 on every generic route; a caller's own bot-exhibition game is readable (GET) there.
- C16. `ReplayFile.rules?: Ruleset` (optional field, additive). Exporters always include it; it is required to verify
  `practice-v1` replays; importers use it (and check `rules.version === rulesetVersion`) instead of guessing.
- C17. `GET /challenges` → 200 `Page<ChallengeSummary>`; `POST /challenges/:id/attempts` → 201 `GameResponse` for a
  new attempt, 200 `GameResponse` when resuming; consumed/completed attempt → 409 `REVISION_CONFLICT`-free 403 `FORBIDDEN`.
- C18. WebSocket adds `match.updated` (payload `{ match: MatchView }`) for lobby join / match start / seat progress.
  Season rows (incl. `duel-v1` and `ranked-v1` active seasons) are seeded by backend at startup; other services read them.
- C19. Casual best-score board counts all `classic-v1` games (server- or client-seeded). It is a casual board and not
  tamper-proof (seed choice, undo); ranked challenge standings are the competitive board. Documented in the UI/README.
- C20. Ranked and duel API responses omit `state.rng` (SEC-R2-06); tests needing a full state build it from
  `newGame(rules, seed)` or read it from the database.
